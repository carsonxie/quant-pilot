## 1. 目标、范围与用户流程

### 1.1 产品定位

一个以ETF为主的个人量化辅助决策与投研系统：持续取得数据，运行明确规则，输出可执行且可追溯的建议，并比较真实执行、主动策略和长期配置基准的结果。

- 项目资金少于10万元人民币，首版只管理划给项目的资金。
- 以境内上市、人民币交易的宽基、行业、跨境、商品ETF为主，可按配置纳入债券ETF；现金单独处理。
- 年化10%–15%、最大回撤尽量低于20%是投资愿望，不能承诺或作为软件必然达成的结果。
- 只做多、不加杠杆、不自动下单、不做日内或高频策略。个股与NLP属于远期方向。
- 每周约10小时开发，盘后日常审核约10分钟；需要交易时在预定市场时段手动执行并反馈。
- 现阶段以确定性数据和规则为主，不要求LLM参与日常投资决策。

### 1.2 工作流程及用户可见结果

数据更新 → 校验可用性 → 计算各策略目标 → 应用策略风控 → 与相应账户比较 → 形成交易建议或无操作说明 → 展示／推送 → 用户反馈 → 更新真实账本 → 绩效与研究评估。

| 用户问题 | 系统输出 |
| --- | --- |
| 现在持有什么 | 项目账户份额、可卖份额、现金、估值时间、未对账状态 |
| 应持有什么 | 策略／版本、目标日期、各目标权重与现金权重 |
| 为什么调整 | 原始信号、风险覆盖、实际偏离和成本过滤的原因 |
| 需要做什么 | 买卖份额、估计金额、参考价、有效期、优先级与依赖条件 |
| 有没有执行 | 成交、部分成交、拒绝、延迟、过期及其原因 |
| 结果怎么样 | 净值、出入金、持仓贡献、成本和同口径基准比较 |

每日拉数不意味着每日换仓。允许无交易、无候选或目标空仓，并给出原因。推送成功不代表成交。

## 2. 技术栈与存储要求

| 能力 | 保留选型 | 范围 |
| --- | --- | --- |
| 语言和依赖 | Python、uv、锁文件 | 优先保持现有兼容版本，升级独立验证 |
| 数据计算 | Polars、pandas、numpy | 使用标准数据契约，避免模块直接读取任意文件 |
| 主存储 | DuckDB | 行情、元数据、运行记录、目标、建议与账户事件 |
| 缓存 | 按需Parquet | 可由指定数据版本重建，不作为真实账户权威来源 |
| 回测 | 自研日线循环 | 以现金、份额、事件和成交时序为核心 |
| 对照工具 | vectorbt | 在共同支持的简单策略上验证；适配能力按锁定版本核查 |
| 因子评估 | alphalens-reloaded或等价轻量统计 | 不为适配库而改变已定义的样本和收益口径 |
| 展示 | Streamlit + Plotly | Phase 0单页；后续在同一入口按需扩充 |
| 调度与推送 | Cron或轻量调度，现有PushPlus等 | 时区明确，幂等，失败可追踪 |
| 模型 | scikit-learn、LightGBM/XGBoost；PyTorch可选 | Phase 2按证据引入 |

数据源以Akshare为主，适配器接口保留。JQData或其他来源按实际权限、覆盖和成本启用；接口限额、可用字段和历史时点能力需验证，不把“免费无限制”视为保证。

首版DuckDB采用统一写入口与批量事务。面板、导入和日任务的并发访问必须协调；单文件不自动消除状态不一致。允许通过一致快照服务展示，不能采用无协调的多进程写入。[DuckDB并发说明](https://duckdb.org/docs/current/connect/concurrency.html)

原始来源数据和修订记录可追溯；行情当前视图可以幂等更新，历史运行绑定数据快照或可重建版本。真实成交／出入金采用有来源的事件记录，更正保留关联，不由行情UPSERT或策略重算覆盖。

## 3. 领域对象与账户边界

以下是概念契约和最低信息要求，具体表名、类名及索引由plan确定。

### 3.1 账户、策略与模拟资金

- 真实账户：项目专用资金的实际账本，有独立 account_id 和人民币计价口径。
- 模拟账户：每个策略／基准／实验独立记账，标明 mode（backtest／paper／real）及策略版本。
- 同一个真实项目账户首版只绑定一个明确启用的建议来源；研究策略和基准可同时比较，但不能各自争用全部真实现金。
- SAA基准不产生默认真实交易指令，不把其虚拟资产与真实资产加总。
- 同券商其他交易如影响了划给项目的资金或份额，必须记录项目资金变动或对账更正；不能默认为可用。
- 初始导入需要现金、持仓份额、估值时点、可卖情况和来源。无法还原持仓成本时，不伪造此前盈亏；从可信起点计算区间表现。

### 3.2 四类记录

| 类型 | 必须包含的信息 | 不得混同 |
| --- | --- | --- |
| 策略目标 TargetPortfolio | target_id、strategy_id／version、mode、as_of、decision_time、完整目标权重（含现金）、数据／配置／池版本、信号与风险原因 | 目标权重不代表已成交 |
| 真实账户 AccountState | account_id、state_id、event_cutoff、现金总额及可用／可取／预留、持仓份额及可卖份额、估值价格与时效、应收权益、核对状态 | 昨日目标不能当作今日账户 |
| 交易建议 TradeProposal | proposal_id、target_id、account state_id、symbol、方向、数量、目标／实际权重、参考价与时间、金额与费用估计、有效期、优先级、依赖、状态及原因 | 建议价不是成交价，发出建议不更新份额 |
| 执行反馈 ExecutionFeedback | feedback_id、proposal_id（允许标记非系统交易）、成交编号、时间、份额、价格、费用；或未执行／部分执行／拒绝／延迟原因及录入来源 | 用户点击“已查看”不是成交 |

一条建议可关联多笔成交；一笔外部成交有稳定去重标识。建议数量与累计成交要可核对；超额或非系统交易保留真实事实并告警，不强行截成建议量。

目标需要完整表达保留与清零；缺失一只旧持仓不能被默认为继续持有。建议被新目标替代或过期后不继续累计为待买数量；重新建议必须参考最新账本及未完执行状态。

### 3.3 账户事件与更新约束

事件至少包括：初始余额／持仓、入金、出金、买卖成交、费用、现金分红、份额变动和对账更正。交易时间与导入时间分开，迟到反馈不能悄悄改写已发布报告，应产生修订版本。

账户状态由事件和估值生成，可由可信起点回放；手工对账差异通过有原因的更正处理，不能直接覆盖而丢失来源。

净资产 V = 现金 + Σ(持仓份额 × 可用估值价) + 应收权益 − 应付费用。应收权益在实际到账后转入现金，不重复计资产。可交易现金不得包含尚不可使用的应收分红或项目外资金。

实际权重 w_i = 持仓市值_i / V；现金与应收等剩余项目需展示或明确归类。总权益非正、关键估值缺失或持仓尚未对账时，暂停生成可执行数量，保留研究目标和问题说明。

## 4. 数据与ETF池管理

### 4.1 信息可用性与价格口径

每项关键数据记录 observation_time／统计期、published_at（适用时）、available_at、source、fetched_at及数据版本。回测只能使用 available_at ≤ decision_time 的值；事后抓取的历史记录若无法证明历史可用性，报告相应限制。

低频数据按可用时间对齐后才能前向填充，并限定新鲜度；价格缺失可用于带标记的临时估值，不可用于虚构成交。历史时点不足时不能以今天的产品属性回填全部历史。

数据至少区分原始OHLCV、交易额、复权／权益事件、研究用收益序列、NAV／IOPV。价格单位、货币、交易额与份额量不得混用。跨境ETF记录境内交易日历及底层资产／净值时间，避免同日标签引入未来信息。

### 4.2 四层池管理

| 层次 | 回答的问题 | 输出 |
| --- | --- | --- |
| 配置范围 AllocationUniverse | 希望覆盖哪些资产类别、市场和风格 | 资产类别／市场／指数／风格的分类和允许范围 |
| 产品候选池 ProductUniverse | 同一暴露使用哪只ETF | 候选产品、比较指标、替代关系、入池／出池依据与生效版本 |
| 当日可交易池 TradableUniverse | 当前哪些可新买、可继续持有、可卖 | 分项检查结果、买卖许可、可用性、失败原因 |
| 实际持仓 Holdings | 项目确实持有什么 | 来源于账户事件，独立于当日筛选结果 |

不能把ETF从可买池剔除等同于其已经卖出。停牌、溢价、流动性下降、退市／清算等应分别处理；持仓仍需估值、风险提示及后续退出记录。ETF并非没有终止、流动性或折溢价风险。[投委会ETF风险说明](https://www.ifec.org.hk/web/sc/investment/investment-products/etf/benefits-and-risks/major-risks.page)

### 4.3 产品元数据和选择要求

最低分类：symbol、交易所、上市／终止日期、跟踪指数、资产类别、市场、风格、交易币种与底层汇率暴露、基金类型、交易规则及其生效区间。

研究与筛选指标：资产规模、历史成交额、费率及生效日期、跟踪偏离／跟踪误差、NAV／IOPV时间与有效性。跟踪质量比较需统一币种、分红和指数收益口径；不能用同一指标混比跟踪不同指数的产品。

同指数产品选择属于实现工具比较；不同指数／资产选择属于暴露设计。相关性矩阵与聚类用于发现冗余，同时报告窗口、覆盖与样本数，不按单一阈值自动删掉所有相似产品。

产品池低频评审，市场禁买与风险事件可即时生效。历史回测使用当时的池版本；无法重建时标明条件性研究。样本不足的新ETF不能为了凑长期历史而视为自指数诞生起就可交易；指数代理需单独标注为合成研究。

### 4.4 质量护栏与缺失处理

检查结果采用 pass／fail／unknown／not_applicable，并保留理由。核心规则：

- 非法价格、单位冲突、重复键冲突、未来时间等阻断受影响计算。
- 跳涨跌需结合产品交易规则、原始与复权口径、分红／拆分及交易日历判断；真实市场极端行情不能自动改写为平滑数据。
- 疑似异常在核验前隔离，不产生新增风险的可执行建议；保留问题和已有持仓风险提示。
- NAV／IOPV缺失、过期或与市场价格时点不匹配为unknown，不能静默通过溢价筛选。该检查为必需的产品在unknown时禁止新买；减仓是否可执行由交易与价格有效性决定。
- 指标缺失须标明影响范围。必须指标缺失则对应策略不可用；可选维度降级须显式版本和原因，不自动改变权重而冒充原策略。
- 双源核对包括日期、币种、价格／收益逐点误差、分红与缺失覆盖；相关系数只是辅助统计，不独自决定通过。
- 免费来源的失败有重试、退避、更新状态和报警；不能把未更新的数据当作当日新数据。

## 5. 策略目标、配置与再平衡

### 5.1 三个首版对照

| 标识 | 行为 | 用途 |
| --- | --- | --- |
| B0：固定初始配置买入持有 | 按初始配置买入，此后不做日常权重调整 | 判断不再平衡时的路径 |
| B1：SAA＋阈值再平衡 | 预设目标，周期检查实际模拟权重，超带调整 | 正式配置比较基准 |
| A：主动策略 | 五层漏斗及经登记的规则版本 | 评估择时、选品、权重和风控增量 |

B0与B1使用同一初始资产映射和权重，A可以独立配置。三者使用同一比较日历、初始资本、允许产品范围、价格和成本框架；策略导致的实际费用不同，不能人为设成相同金额。

公平比较同时记录现金、资金闲置和外部现金流政策。无外部现金流的标准研究作为主要对照；模拟真实入金时各账户接受相同金额与时点。B0新增资金如何分配必须预先定义（首版可设留现金），不能事后择优。

SAA权重在一次研究／评估区间内预先确定并版本化。年度评审或资金需求变化可形成新版本，不能把新权重追溯应用到旧历史来掩盖表现。用全样本优化出的配置不能宣称从研究起点就已知。

### 5.2 主动策略与宏观信号范围

原趋势／宽度模块可继续作为初始候选。MA20／MA60、市场宽度窗口、旧五维权重与得分映射均属于待登记的策略参数，不是市场规律。

- 明确宽度分母：全A股票、指定股票样本或ETF代理。只有20只ETF的数据时，不得标为“全A市场宽度”。
- 宏观得分记录输入覆盖、启用维度、标准化方法和有效权重。只启用部分维度时，归一化方法须显式，不能缺失直接当0。
- A股信号默认限制 A 股分类的账户权重合计；其余资产仍遵守独立账户上限。若某策略研究采用全组合择时，应另立显式版本、说明逻辑并独立评估，不作为默认。
- 单日骤降若与数据源、池版本、分母或评分方法变化重合，先检查可比性，不能自动认定市场骤降。
- 波动率、资金流向、信用利差等逐个通过数据可用性和增量验证后再研究接入；取消P0先建设全部宏观管道的要求。
- 初始选择器须明确且可复现。若Phase 0只是固定池／低波排序，则如实命名，不宣称已经实现多因子选优。

### 5.3 配置算法与约束

- 等权：w_i ∝ 1；保留为简单对照。
- 波动率倒数：w_i ∝ 1/σ_i，算法标识 inverse_volatility。
- 方差倒数：w_i ∝ 1/σ_i²，算法标识 inverse_variance。
- 初始主动配置按原意使用 inverse_volatility；若现有代码是inverse_variance，保留旧版本作为历史对照，迁移后重跑，不静默改变旧报告定义。
- 波动率窗口、日历、收益口径、最低样本与波动率下限必须声明。零波、缺失、短历史不能产生无限权重。
- 目标满足做多、总预算、单产品及资产类别上限。裁剪后无可行分配时保留现金并解释，不能突破上限强行满仓。
- “最多K只”不应默默按数据库顺序截断；排序及并列规则显式。
- 风险平价与收缩协方差放Phase 1.5按证据研究，不承诺必然比简单配置更好。

### 5.4 再平衡规则

比较 actual_weight 与 target_weight，而非仅比较新旧目标。除真实账户外，B1也用自己的模拟实际份额计算漂移。

- 偏离 d_i = actual_weight_i − target_weight_i。
- 首版常规触发使用绝对权重偏离：abs(d_i) ≥ band_i，band以比例值保存并以百分点显示。例如0.05表示5个百分点，只是示例。
- 目标不变但实际从20%漂移到28%，仍应检查触发；真实未执行也仍然保留差额。
- 检查周期与目标更新周期分别定义；首版B1可采用每周最后一个交易日盘后检查，节假日随交易日历处理。
- 首版越界后，对当前越界资产提出调回目标的交易；未越界资产不为追求全组合精确对齐而自动交易。费用和整数份额允许留下剩余偏离。
- 零目标的已有持仓视为策略退出；首次建仓、明确退出、风险退出和出金需求不因普通带宽而永久跳过。
- 总量、现金和可卖限制统一校验；无法完成的差额留为可解释的未完成目标，下一轮按最新状态计算，不盲目重复累加。
- 相对阈值、调回带边界、成本优化调仓为后续候选，需独立版本。首版不同时混入多种未定义阈值。

成本过滤、最小金额和最低持仓仅约束普通调整，不能压制合规可执行的风险退出。费用预估可能阻止小额常规买入，但不能抹掉退出事件。

### 5.5 风险优先级与重新进入

处理顺序为：交易与数据可用性约束 → 账户硬约束／策略暂停 → 明确风险退出与暴露上限 → 常规目标调整 → 成本及持有期过滤。约束不能被下游优化器放宽。

首版ATR为盘后规则：在统一价格口径下，以实际持有期间维护最高价及ATR，止损线只按规定上移；用T日收盘价与当时有效止损线比较，触发后最早下一可交易时段执行。日内最低价穿线不等于以止损价成交。若增加盘中触发模拟，另行定义事件顺序和数据依据。

风险退出先生成清零或减仓目标并保留退出原因，随后数量规划仍受可卖份额和停牌等约束。无法卖出时持续展示剩余风险，不能从账本删掉持仓。

止损排除的产品不得在同一轮“二次优化”中被重新买回。首版重新进入至少满足：退出已反馈或模拟完成；有一个后续决策日；当前退出条件解除；配置的冷却条件满足；新一轮选择仍合格。高水位和止损状态在实际重新建仓时按规则重置。具体冷却参数在运行前声明，不能由旧15%防抖隐式替代。

## 6. 交易建议、回测和运行要求

### 6.1 可执行建议

建议使用最新可信项目账户状态，数量需考虑参考价格、费用、最小交易单位、现金与可卖份额。买入按适用交易单位向可负担方向取整；卖出按产品规则处理整手及零碎份额，不卖超实际可卖量。

首版不假定当日卖出一定成功。依赖卖出资金的买入明确标为条件建议；卖出失败或开盘价格变化导致资金不足时，缩减／延期买入并记录原因，不生成负现金。

参考价记录来源与时间。下一日开盘为回测基准之一，不保证用户能以该价成交。建议须有有效期、持仓更新时间要求和价格偏离提示；账户发生新交易后旧建议需重算或作废。

目标权重变化、实际权重漂移、首次建仓、池退出、风险退出、资金需求分别记录原因。新旧目标差异只用于解释信号变化，不能代替账户调仓判断。

### 6.2 时间与成交模拟

- T日盘后作决策，最早下一交易日有效开盘或另行预定的可执行时段成交。
- 单纯日线回测不能声称知道盘中价格先后；VWAP只有在数据、单位与执行假设可支持时才能启用，不要求Phase 0实现。
- 不使用决策后才知道的下一日全日成交额、最高／最低价来决定开盘买卖数量。
- 买入份额的可卖时间按标的、市场日历和规则版本记录；可用现金、可取现金与结算义务分别处理。交易规则需按适用市场核实。[上交所ETF常见问题](https://www.sse.com.cn/assortment/fund/etf/question/)
- 停牌、无有效价格或受交易限制时允许不成交。不能仅因为日线出现某价就断言限价委托必然成交。
- 没有足够盘口数据时采用有说明的保守成交假设，报告其局限；不编造精确撮合能力。

### 6.3 价格、权益与成本

研究价格与实际撮合价格分离。回测份额／现金账本使用原始可成交价格，现金分红按权益日确认应收、到账日增加现金，份额变动按事件记录；缺少必要权益数据时须标记该结果不可作为完整账本验收。

可使用总收益序列进行单独的数学研究对照，但不得同时重复计入分红。复权变化需要使受影响缓存失效或产生新数据版本。只回溯10天更新不能天然保证全部前复权历史一致。

成本至少区分买／卖佣金率、最低收费政策、相关税费、买卖价差／滑点与冲击假设：

- 费率来自实际账户或明确研究配置，按生效期记录；未知时使用标注的研究情景，不伪称真实费率。
- 双边成本是实际买入和卖出的合计，不得在每一边重复扣整个双边费率。
- 滑点若已体现在成交价格中，绩效报告可以展示估计影响，但不能再次从现金扣除。
- 用ETF实际净值／市场价格研究时，基金日常管理费用通常已反映在基金资产表现中；如额外估计费用需声明口径，避免重复扣费。
- 旧 max(0.15%, 交易额／日均成交额 × 0.5%) 仅可保留为明确命名的旧压力情景，不能作为经校准的市场冲击定律。
- 实验至少有基准成本和更不利成本情景；零费用只用于数学对照或单元验证。

### 6.4 账本与引擎验收

关键证据是逐事件份额和现金、每日权益、费用及分红的可核对性。数值精度与舍入规则预先定义。

需要覆盖：买入持有、分红、部分成交、拒绝成交、停牌、价格跳空、现金不足、出入金、风险退出和重复运行。零价格变动且无其他收益时，单独入金应增加资产但不提高收益率。

自研引擎与vectorbt仅在共同定义的可比案例下比较交易、份额、现金和净值逐点误差。相关系数高或与沪深300指数年度收益差小于1%，都不能单独证明正确。

无未来信息检查包括追加／改变未来数据不改变过去信号，以及宏观可用时间、ETF历史入池、跨境时间、标签和复权版本等相关路径。少量测试通过不能对全部未来函数作绝对保证。

### 6.5 调度、通知与展示

- 调度按交易所日历与时区判断，首次／增量／重跑可追踪；同一运行可复现且不重复生成有效建议、成交或通知。
- 运行状态区分数据失败、策略不可用、正常无交易、建议成功和通知失败。
- 关键数据缺失时阻断相应新增风险建议，同时保留账户与未处理风险提示。
- 业务结果先可靠保存，再推送；失败重试不重复计账。API密钥／推送token置于环境或受保护配置，不写入日志和公开文档。
- Phase 0面板至少展示今日信号、原因、持仓和可得净值；真实／模拟、数据截止、是否对账及历史限制必须可见，不能用目标列表充当真实持仓。
- Phase 0.5补目标与实际偏离、现金、建议有效期、反馈和基准对照；Phase 1.5再扩展归因视图。

## 7. 研究评估与分层归因

### 7.1 实验、因子与版本

规则阶段即记录：experiment_id、代码版本、依赖版本、数据版本、池版本、配置、成本、训练／验证／测试时间、试验目的、全部结果与结论。失败实验不删除，修改参数或池子产生新记录。

因子注册表保留结构化YAML，以定义为主：name／version、经济假设、formula、输入与单位、回看窗口、数据可用性、缺失政策、预处理、预测期限、适用截面、代码入口、status。IC等指标放带实验与样本版本的评估记录；YAML如展示汇总，必须引用来源，不放无时间上下文的永久“IC均值”。

注册检查验证定义与入口的一致性，但不得为了通过质量门槛修改数据或强行让所有候选因子有效。

Phase 1先完整研究少量候选（例如动量和低波），取消至少8个因子的硬数量要求。相同收益来源的多个期限不是多个独立证据。

### 7.2 指标及统计定义

| 指标 | 定义与注意事项 |
| --- | --- |
| RankIC | 每个决策时点，对当时可比且标签已成熟的截面，计算得分与指定未来收益的Spearman相关 |
| ICIR | IC序列均值／标准差；记录频率、期数、样本缺失和年化约定 |
| 组合IR | 对同频主动收益a_t = r策略,t − r基准,t，常规年化为sqrt(m) × mean(a_t)／std(a_t)，说明相关性与年化假设 |
| 夏普 | 同频超额于无风险／现金代理收益的均值相对其波动；记录代理、周期和年化方法 |
| 最大回撤 | 可比净值相对历史高点的最大跌幅；不把观察值当作未来上限 |
| 换手与成本 | 明确单边／双边换手分母，分别列费用金额和相对资本的基点 |
| CAGR／TWR／MWR | 依据现金流条件分别报告，不把外部入金当投资回报；MWR可作为后续补充 |

RankIC不是胜率，不能由0.05推算固定两两胜率；Spearman衡量秩相关。[SciPy官方定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html)

默认报告未年化ICIR。分组数随有效截面和并列值确定；样本不足时减少分组或停止该项统计。长短期收益重叠时采用适当稳健标准误／分块重采样，不机械套 t = ICIR × sqrt(n)。多次试验需披露，不把一个p值视为全部验证。

未来收益必须与策略的决策／可执行时间一致；可另报收盘到收盘的纯预测诊断，但不能与可交易收益混称。12-1动量使用一致总收益价格的 P_(t-1月) / P_(t-12月) − 1，或等价对数区间收益；不得直接将两个算术累计收益相减当作精确区间收益。

滚动IC监控只使用已经完成未来观察窗口的标签，不在当日获取未来一期收益。

### 7.3 时间划分与策略增量

- 根据实际产品历史和数据覆盖预先划分开发、验证和最终测试区间。
- 2022–2024不再固定标为纯样本外；一旦用于选规则，明确记录为开发／验证用途。
- 参数邻域、窗口、因子方向和阈值选择在开发／验证中完成；最终测试用于报告，而非看完结果继续改参后仍声称未触碰。
- Walk-forward保持时间顺序，训练数据与标签不能跨入验证时间；Purging／Embargo按标签和信息重叠范围采用，不等到ML才考虑泄露。
- 使用同一价格、现金、成本、期间和产品范围比较B0／B1／A；有条件差异须在报告中列明。
- 模块增量通过预先安排的对照／消融实验评估，如简单轮动、加入宏观、加入ATR、改权重，避免一次性全部变化而无法解释结果。
- 成分变化、上市历史不足、替代指数和数据源缺失均报告；不回填“当时不可交易”的ETF历史。
- 正收益、IC门槛或参数邻域百分比不是工程必过项。允许结论无效或证据不足，并据此保留简单方法。

### 7.4 归因交付边界

| 层次 | 问题 | 交付阶段 | 必要条件 |
| --- | --- | --- | --- |
| 持仓贡献 | 哪些持仓、现金收益与费用贡献了盈亏 | Phase 0.5 | 可核对账本与权益事件 |
| 相对基准表现及模块对照 | 主动策略相对B1有何差异，各模块改变了什么 | Phase 1 | 同口径独立策略记录 |
| 执行偏差 | 用户执行与策略标准执行有何差异 | 原始记录Phase 0.5，分析Phase 1.5 | 决策价格、建议、成交、未执行与匹配资金流 |
| 因子暴露和收益解释 | 所选市场／风格因子能解释多少收益 | Phase 1.5 | 对齐收益、适用因子与足够历史 |
| 风险贡献 | 哪些资产或因子主导风险 | Phase 1.5 | 同频协方差、当时持仓和稳定估计 |
| Brinson（条件适用） | 相对基准的配置、选择和交互贡献 | Phase 1.5按适用性 | 明确分类、基准与组合分类收益 |

基础金额核对：期末权益 − 期初权益 − 净外部入金 = 投资盈亏。持仓、分红／现金收益、实际费用和其他明确项目加总应与投资盈亏一致，未解释差额单独展示。期间收益贡献若需跨期加总，使用说明的链接方法，不能直接把每日百分比相加。

TWR按外部现金流将收益分段链接；只有日线数据时，现金流时点采用明确约定并标注近似，不能把未知时点当作精确TWR。外部入金不增加收益，分红属于投资收益，二者分别记录。

Brinson通常分解配置、选择和交互，不自动识别宏观择时或“真实Alpha”；ETF每类仅一个产品时，选择效应可能信息有限，不强行制造贡献。[CFA Institute归因说明](https://rpc.cfainstitute.org/research/cfa-digest/2017/04/using-brinson-attribution-to-explain-the-differences-between-time-weighted-twr-and-money-weigh)

因子解释使用明确币种和时间的模型，例如 r_p,t − r_f,t = α + Σβ_k f_k,t + ε_t。显示Alpha估计、误差／不确定性、窗口、残差及模型限制；多个宽基ETF回归可作暴露代理，不把共线代理的系数直接称为稳定的纯风格贡献。收益残差不等于投资技能，风险贡献也不是收益贡献。

执行偏差分析以预先定义的标准执行路径作对照，分出延迟、价差、费用、部分／未成交和非系统交易；不能把所有真实盘与回测差异都归因于“用户没纪律”。策略版本、行情和资金流不同应先解释。

### 7.5 风险贡献与策略状态

组合波动 σ_p = sqrt(wᵀΣw)；MRC_i = (Σw)_i / σ_p；RC_i = w_i × MRC_i，ΣRC_i = σ_p。若采用方差风险贡献，应单独命名并验证其加总为组合方差。

风险平价比较RC或归一化RC，不只比较MRC。现金、零波动和负风险贡献的处理应声明；σ_p为零时不除零。仓位上限可能使严格等风险不可行，应报告残余差异，不能放松硬约束以凑验收。

策略状态至少为 research、paper、active、watch、paused、retired，记录版本、原因、证据、操作人和时间。首版watch主要提示和复核，不凭三个月IC为负自动改变权重。

数据／账户故障可暂停新增建议；暂停不等于持仓已清仓。保留持仓展示和适用风险提示。策略研究失效后的降仓或退出政策需提前声明并人工执行；恢复要求问题关闭、数据和账户可信、观察证据满足预定标准。旧版本的评估不能自动替新版本取得active状态。

样本案例至少覆盖：目标20%未变、实际漂移到28%；昨日建议未执行；卖出只部分成交；现金不足；重复导入；不足一手；止损10%持仓不被旧15%门槛压制；NAV缺失；ETF停牌但仍持有；无行情收益时入金不改变收益率。

完整模拟结果和真实账本不得混写。基准参数可以用标注的研究配置验收，不要求在本阶段决定实际SAA投资比例。

### 8.3 Phase 1 — 少量策略验证

目标：先建立可信比较，再决定保留哪些模块。

交付：少量候选因子及注册检查、适合ETF的预处理、RankIC／ICIR及分组诊断、简单权重对照、B0／B1／A比较、模块消融、时间划分和成本压力报告；vectorbt在可比案例下作辅助验证。

验收：实验可复现、公式和样本口径正确、开发／验证／测试用途清楚、参数邻域及失败结果披露、净收益和风险／换手一起报告。结论可以为无效或证据不足，不强制每个因子达到IC门槛或策略年化收益达到8%。

宏观新增维度、第二个因子或更复杂轮动逐个研究，未证明增量可停用。固定SAA基准不因主动策略表现差而事后更换来制造超额。

### 8.4 Phase 1.5 — 风险解释与策略治理

交付：资产风险贡献、适用的因子暴露／收益解释、执行偏差、策略状态与失效／恢复记录；Brinson按分类和基准数据适用性实现。风险平价与Ledoit-Wolf作为可选比较方法，不是强制替换。

验收：风险贡献按定义闭合；暴露窗口、模型、误差和残差透明；实际与标准执行之间的数据／策略／资金差异先核对；暂停不伪装为清仓；恢复有证据；所有规则变更有版本。

样本或因子数据不足时输出不可评估原因，不伪造Alpha或风险解释。此阶段的监控不默认执行自动因子降权。

### 8.5 Phase 2 — 可选ML增强

前提：前述工程与研究流程可用，并存在简单方法尚未解决的明确问题。引入LightGBM／XGBoost，PyTorch原型可选。

交付：标签与特征定义、适用的时间验证和Purging／Embargo、实验追踪、模型解释、与简单方法同口径比较。固定随机种子、代码、依赖和环境；在声明环境内规定结果容差，不承诺跨硬件逐位相同。

模型没有增量也算完成研究，不要求IC必涨0.02或必达p<0.05。新增模型不得因为刚训练完成就自动成为真实账户建议来源。

### 8.6 Phase 3 — 远期范围

NLP新闻／研报情绪、个股、Black-Litterman、遗传表达式、深度时序特征等按具体问题重新立项。股票范围要重新评估财报PIT、生存者偏差、停牌与退市、税费等；不以当前ETF实现已完成为理由默认全部支持。

核心／卫星结构、估值定投、网格、目标波动率、双动量等保留研究候选；未来采用时需重新定义资金范围和规则优先级。

### 8.7 三种Gate

| Gate | 判断 | 不要求 |
| --- | --- | --- |
| 工程Gate | 数据、公式、时序、状态、账本和错误处理正确，有必要验证 | 不要求取得指定回测收益 |
| 研究Gate | 按声明方法完成研究，披露失败、不确定性与局限 | 不要求每个候选都有效 |
| 真实账户启用Gate | 账户已核对，实际配置明确，影响资金安全或结论正确性的缺陷关闭，前瞻运行证据充分，用户明确启用相应策略版本 | 不因工程或研究完成自动启用 |

收益／回撤偏好可以进入真实账户评估标准，但不能改成“代码必须保证”。前瞻纸上运行时长与评审规则应在开始前声明；运行若干月不是盈利保证。
