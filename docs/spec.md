# Quant-Pilot 项目总体规划 (Project Specification) — v2.0

## 1. 项目愿景与核心定位 (Vision & Positioning)

- **定位**: 一个剥离人类情绪、严格基于统计概率、每日盘后自动推演交易逻辑的**量化辅助决策与投研系统**。
- **投资标的**: A 股市场的宽基 ETF、行业主题 ETF，以及跨境/商品 ETF（构建低相关性的资产配置池）。后期可扩展至高流动性大盘蓝筹股。
- **策略流派**: 混合流派（Hybrid）。自上而下的宏观择时 + 自下而上的截面多因子/ML 预测 + 严格的动态风控。
- **商业目标**: 追求长期复利，期望年化收益率 10% - 15%，最大回撤严格控制在 < 20%。
- **资金体量**: < 10 万人民币（决定了初期持仓集中度与摩擦成本的考量）。
- **工作模式**: 每日盘后自动拉取数据 → 因子计算 → 模型推断/规则打分 → 生成次日交易信号 → 消息推送到移动端。**人工审核并手动执行，不包含全自动实盘下单接口**。
- **人工审核定义**: 每天 10 分钟内完成：①核对信号是否与昨日一致；②检查触发原因是否可解释；③确认资金到位；④若信号要求清仓/大幅减仓，二次确认宏观逻辑后执行。盘中绝对不看盘。

## 2. 核心技术栈与存储架构 (Technology Stack & Storage)

*放弃重型工业级框架（如 Qlib），采用轻量、灵活、高扩展性的现代 Python 数据科学栈，以匹配个人开发者的精力限制，同时为未来的 ML/DL 预留充足空间。*

### 2.1 核心计算与算法栈

- **编程语言**: Python 3.10+ (包管理: `uv`)
- **数据处理核心**: `Polars` (主打高性能时序与截面计算) + `pandas` (兼容复杂生态) + `numpy`
- **回测引擎**: **混合模式** —— `vectorbt` (向量化回测，用于快速原型验证) + **自研轻量回测循环** (用于处理 T+0/T+1 混合撮合、动态仓位上限、自定义冲击成本等复杂场景，详见 4.4)
- **因子评估**: `alphalens-reloaded` (因子 IC/IR 分析、分位数收益测试)
- **机器学习/深度学习**: `scikit-learn`, `lightgbm`, `xgboost`, `PyTorch` (P2 阶段引入)
- **前端与可视化**: `Streamlit` (P1 阶段仅单页面信号面板) + `Plotly` (交互式图表)
- **任务调度**: OS Native Cron (Linux/WSL) 或 `schedule` 库

### 2.2 简化双层存储架构 (The 2-Tier Storage — v2.0 精简)

*原三层架构（DuckDB + Parquet + SQLite）对于 50-100 只 ETF、日线级别的数据量属于过早优化。v2.0 精简为 DuckDB 单文件为主的架构，彻底消除多库之间的一致性问题。*

| 存储层                               | 技术选型                                 | 存储内容                                                                                                                                | 核心职责                                                                                                                                                           |
| :----------------------------------- | :--------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Primary Store** (主数据仓库) | **DuckDB** (`.duckdb` 单文件)    | ①全量历史日线 OHLCV、复权因子、宏观指标、行业映射；②交易信号流水、账户持仓状态、净值曲线；③标的池配置 (Universe)、ETF T+0/T+1 元数据 | **单一真理之源 (Single Source of Truth)**。利用 DuckDB 同时胜任 OLAP（海量时序查询）与 OLTP（交易流水事务），`UPSERT` 机制完美处理历史初始化与每日增量追加 |
| **Compute Cache** (计算缓存)   | **Parquet** (列式文件集，按需物化) | 清洗、复权、对齐后的**宽表**及**因子矩阵**——仅当回测/训练需反复读取时物化                                                 | **计算加速层**。供 Polars、vectorbt 和 ML/DL 模型极速向量化读取与零拷贝内存映射。可随时从 DuckDB 重建，不承载状态                                            |

- **标准数据流向**:
  `多源 API (Akshare/JQData)` → `Polars 内存清洗` → `DuckDB (UPSERT 落盘)` → `特征工程计算` → `Parquet (因子矩阵，按需物化)` → `模型/回测读取`
- **关键简化收益**:

  - 砍掉 SQLite 独立实例，消除 DuckDB ↔ SQLite 之间的状态不一致风险
  - 交易流水、账户状态与行情数据同库，可通过单条 SQL 联表查询（如「回测时在每笔交易上下文中直接拿到当日行情」）
  - P0 阶段甚至可以不物化 Parquet，直接从 DuckDB 查询并转为 Polars DataFrame

## 3. 系统的五层决策漏斗 (The 5-Layer Decision Funnel)

*这是策略的灵魂，所有代码模块均为此漏斗服务。*

### 第一层：宏观择时 (Macro Timing) — 决定总仓位上限

采用**五维度复合打分系统**，输出 0-100 的市场状态得分，映射到总仓位上限，防范系统性风险。

| 维度                  | 权重 | 核心指标代理                              | 逻辑说明                               |
| :-------------------- | :--: | :---------------------------------------- | :------------------------------------- |
| **① 趋势动量** | 30% | 沪深300的 20/60 日均线排列状态            | 顺势而为，多头排列给高分，死叉给低分   |
| **② 市场宽度** | 25% | 全A股站上 20 日均线的股票比例             | 衡量上涨的普适性，避免"赚了指数不赚钱" |
| **③ 波动率**   | 20% | 沪深300 过去 20 日年化波动率              | 反向指标。高波=高风险=低分，低波=高分  |
| **④ 资金流向** | 15% | 北向资金/主力资金 20 日累计净流入 Z-Score | 跟踪"聪明钱"的边际变化                 |
| **⑤ 宏观环境** | 10% | 信用利差 (AAA企业债-国债) 变化方向        | 衡量宏观流动性与风险偏好（低频指标）   |

> **P0 阶段仅实现维度 ① 和 ②。维度 ③④⑤ 在 P1/P2 逐步加入。**

**数据时滞处理（维度⑤特别约束）**：

- DuckDB 中为每个宏观指标额外存储 `publish_date` 字段（该数据实际可被获取的日期）
- 回测与实盘中，T 日仅可使用 `publish_date <= T` 的宏观数据（而非指标的统计日期或截止日期）
- 维度⑤在 P0 阶段即搭建数据管道，验证 Akshare 对信用利差数据的覆盖质量和延迟特征，**但在 P1 后期才正式纳入打分**，避免因数据质量问题污染早期信号

### 第二层：标的清洗 (Universe Filtering) — 决定可交易池

- 剔除日均成交额 < 500 万的流动性枯竭标的
- 剔除存在严重溢价（市场价格大幅偏离 IOPV 净值）的跨境/行业 ETF
- 剔除上市时间不足 60 个交易日的新标的
- 增加流动性集中度检查：若计划持仓金额 / 标的日均成交额 > 0.5%，触发警告（你的 10 万资金对微盘 ETF 的冲击不可忽略）

### 第三层：因子打分/预测 (Alpha Scoring) — 决定买谁

- 对通过清洗的标的池，计算截面因子（量价、基本面、宏观情绪等）
- 对因子进行去极值 (MAD)、缺失值处理、标准化 (Z-Score) 及行业/市值中性化
- 根据因子权重进行加权打分，或输入 ML/DL 模型预测未来 N 天胜率/收益率，选出 Top 3-5 只标的
- 引入换手率惩罚：若新旧信号的目标仓位差异 < 15%，不触发调仓（详见 4.3）

### 第四层：组合优化 (Portfolio Allocation) — 决定买多少

- 摒弃简单的等权分配
- P0 阶段采用 **波动率倒数加权**（简单、鲁棒、可解释）
- P1 阶段升级为 **风险平价 (Risk Parity)**，结合协方差矩阵收缩估计 (Ledoit-Wolf)，确保每只标的对组合总风险的贡献度相等

### 第五层：风控执行 (Risk Management) — 决定何时卖

- 摒弃僵化的固定比例止损
- 采用 **ATR (真实波动幅度) 动态移动止损**：`Trailing_Stop = 最高价 - N * ATR`
- 叠加第一层的宏观择时信号：若宏观得分骤降（单日下降 > 30 分），触发全局强制减仓至安全仓位

## 4. 系统模块架构与扩展性审核 (System Architecture)

*本架构经过前瞻性设计，确保在引入多源异构数据、深度学习及 NLP 时，无需重构核心骨架。*

### 4.1 数据层 (Data Layer) — 多源异构数据融合

- **目标**: 构建干净、无偏、防坑、支持多频对齐的底层数据仓库。
- **扩展与完善要点**:
  - **多源适配器 (Fetchers)**: 设计统一的 `BaseFetcher` 接口，支持 Akshare (量价/宏观)、JQData (财务/复权)、甚至未来的 Tushare 和爬虫数据源。
  - **多频数据对齐 (Frequency Alignment)**: 财务数据（季频）、宏观数据（月频）与日线（日频）对齐时，**必须严格使用 Forward-fill (前向填充)**，并引入"发布延迟 (Reporting Lag)"概念——所有宏观数据必须携带 `publish_date` 字段，严禁使用 T 日尚不可知的数据参与 T 日决策。
  - **行业与概念映射**: 维护一套本地的"标的-行业-概念"映射表（存入 DuckDB），为后续的行业中性化和板块轮动提供基础。
  - **数据质量护栏**: 写入 DuckDB 前，必须在内存中拦截价格为负、时间戳断裂、单日涨跌幅 > 20%（ETF 极少出现）、财报"总资产 < 0"等脏数据。拦截后**阻断流程并报警**，绝不把脏数据喂给策略。
  - **双源交叉验证**: 每周自动用 JQData 拉取核心宽基 ETF 数据，与 Akshare 数据计算相关系数，若 < 0.999 则触发警报。

### 4.2 因子工程层 (Factor Engineering Layer) — 从规则到深度学习

- **目标**: 将原始多源数据转化为具有预测能力的 Alpha 信号。
- **扩展与完善要点**:
  - **因子注册表 (Factor Registry) — 结构化强制维护**:

    > ⚠️ **v2.0 变更**：因子注册表从 Markdown 文档改为 `config/factor_registry.yaml` 结构化格式。每个因子必须包含字段：`name`, `formula`（数学公式）, `category`（量价/基本面/宏观）, `ic_mean`, `ic_ir`, `code_path`（函数位置）, `status`（active/deprecated）。
    >

    配套 CI 检查脚本（`make factor-check`）：

    - 验证 YAML 中注册的每个因子都有对应的可导入 Python 函数
    - 验证 `factor_engineering/` 目录下的每个因子函数都在 YAML 中注册
    - 每次 `git commit` 前自动运行，防止"写了代码忘记注册"或"注册了幽灵因子"
  - **表达式引擎预留**: 预留基于字符串解析的因子表达式接口（类似 Qlib 的 `$close/Ref($close, 1)`），方便未来进行大规模遗传算法因子挖掘。
  - **非线性与深度学习因子**: 预留接口，支持将 PyTorch 训练的时序 Embedding 或 Autoencoder 隐变量作为"高阶因子"接入截面打分体系。

### 4.3 策略与模型层 (Strategy & Model Layer) — 实验追踪与解耦

- **目标**: 组合漏斗逻辑，输出目标持仓权重，并管理模型生命周期。
- **扩展与完善要点**:
  - **策略解耦**: 宏观择时、标的清洗、截面选股、组合优化、风控执行必须是独立的类，通过标准 DataFrame 接口传递数据。**每个漏斗层可独立单元测试**。
  - **模型实验追踪 (Experiment Tracking)**: 基于 DuckDB 的轻量级实验记录表（无需引入 MLflow 等重型工具），记录每次 ML/DL 模型训练的超参数、训练集/验证集划分、样本外 IC 衰减曲线。验收要求：任何被认定为"最优"的参数组合，在其 ±20% 邻域内的参数都必须有相似的样本外表现（防止"参数孤峰"过拟合）。
  - **信号衰减与平滑**: 引入换手率惩罚机制——若新旧信号的目标仓位差异 < 15%，不触发调仓。设定最低持仓周期（信号发出后至少持有 3 个交易日），避免震荡市中被摩擦成本"凌迟"。

### 4.4 回测引擎层 (Backtest Engine Layer) — 混合模式，极致现实主义

- **目标**: 在历史数据上无偏、严苛地验证策略。
- **混合回测架构 (v2.0 新增)**：

  | 引擎                                                | 适用场景                                                                   | 特点                                                                                                     |
  | :-------------------------------------------------- | :------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------- |
  | **vectorbt**                                  | 快速原型验证、简单等权/固定权重策略、因子 IC 快速回测                      | 向量化极速计算，一行代码出全套绩效指标。但原生不支持 T+0/T+1 混合撮合和动态仓位上限                      |
  | **自研轻量回测循环** (`CustomLoopBacktest`) | T+0/T+1 混合标的池、宏观择时动态仓位上限、自定义冲击成本模型、复杂止损逻辑 | 纯 Python for-loop，约 200-300 行。日线级别、100 只标的完全无性能瓶颈。每个撮合步骤可 step-through debug |
- **自研回测循环核心需求规格**：

  1. **标的元数据驱动撮合**: 读取 DuckDB 中标的是 T+0（跨境/商品 ETF）还是 T+1（A 股 ETF），自动路由不同交收逻辑
  2. **动态仓位上限**: 每日从宏观择时模块读取仓位上限（0-100%），约束当日总持仓市值
  3. **多级撮合价格**: 支持以 T+1 开盘价 / T 日收盘价 / VWAP 等多种价格模拟成交
  4. **冲击成本模型**: 对流动性较差的标的，基于「交易金额 / 日均成交额」比值施加额外滑点惩罚
  5. **涨跌停拦截**: 若扩展至个股，自动拦截涨停买不到、跌停卖不出的情况
  6. **生存者偏差处理**: 若扩展至个股，数据库必须包含已退市标的，正确处理退市清算逻辑
- **验收标准**: 用同一简单策略（如 20 日均线交叉）在两个引擎上分别回测，日收益率序列的相关系数 > 0.9999（验证自研引擎的正确性）。

### 4.5 展示与交互层 (Presentation & UI Layer)

- **目标**: P0 阶段仅提供一个**单页面信号面板**（Streamlit），展示：今日信号、触发原因、当前持仓、近期净值曲线。不做多页面仪表盘。
- **P1 阶段扩展**:
  - **绩效归因 (Performance Attribution)**: 将收益拆解为：宏观择时贡献、行业 Beta 贡献、个股/ETF Alpha 贡献、摩擦成本损耗。
  - **指令清晰化**: 推送消息必须包含：标的、方向、目标仓位、触发原因（如"动量因子排名上升至第 2 名"或"触发 ATR 止损，当前价格低于买入价减去 2 倍 ATR"）。

### 4.6 非结构化数据处理层 (Unstructured Data Layer — P3 预留)

- **目标**: 处理新闻、研报、社交媒体等文本数据，提取情绪因子。
- **架构预留**:
  - 原始文本存储于本地文件系统
  - 通过 LLM API 或本地 NLP 模型（如 FinBERT）提取情感得分或主题向量
  - 提取后的**结构化情绪特征**并入 DuckDB，作为独立因子参与第三层打分

## 6. 开发原则与反目标 (Guiding Principles & Anti-Goals)

### 核心原则 (Do's)

1. **防御性编程与数据隔离**: 严格区分 `raw` (DuckDB 原始表，不可篡改) 与 `cleaned/factors` (计算产物，可重建)。对所有输入 DataFrame 进行 Schema 和时间戳连续性校验。
2. **接口驱动与解耦**: 数据层、因子层、策略层之间必须通过明确定义的数据结构交互，严禁跨层直接读取底层数据库或文件。
3. **可复现性与实验追踪**: 所有的随机种子必须固定；所有的 ML 模型训练必须记录超参数与样本外表现；所有配置从 `settings.yaml` 读取。
4. **渐进式复杂度**: 严格遵循 Phase Plan（见第 7 节）的演进路径，**每完成一个 Phase 必须通过验收标准后，才进入下一 Phase**。

### 阶段性克制与反目标 (Don'ts & Not-Yets)

1. **No HFT (拒绝高频)**: 不处理 Tick/分钟级数据，不追求毫秒级延迟，仅处理日线及以上级别。
2. **No Auto-Trading (拒绝自动下单)**: 系统的终点是"生成高质量的交易建议"，不直接对接券商 API 承担程序 Bug 导致的资金风险。
3. **Not-Yet: Unstructured Data (非结构化数据克制)**: 在 P0-P2 阶段**暂不引入** NLP 新闻爬虫和情绪分析。待核心框架稳定且 ML 模型跑出稳健样本外表现后，在 P3 阶段通过预留接口接入。
4. **No Over-Engineering (拒绝过度工程)**:
   - 不引入 Airflow/Kafka/K8s 等重型基建
   - P0 不引入 MLflow（用 DuckDB 轻量实验记录替代）
   - P0 不做多页面仪表盘（单页面信号面板足够）

### Phase 0 — MVP 闭环 (Minimal Viable Pipeline)

> **一句话目标**: 让系统每天盘后自动输出一条有理有据、可执行、可追溯的交易建议。

| 维度               | 内容                |
| :----------------- | :------------------ |
| **预计耗时** | 6-8 周 (60-80 小时) |
| **前置条件** | 无                  |

**交付物清单**:

| #      | 交付物                                                               | 对应模块                              |
| :----- | :------------------------------------------------------------------- | :------------------------------------ |
| P0-D1  | DuckDB 数据库初始化脚本 + Akshare 历史数据全量导入 + 每日增量 UPSERT | `data_pipeline/`                    |
| P0-D2  | 数据质量护栏：单日涨跌幅 > 20% 拦截、缺失值报警、时间戳连续性校验    | `data_pipeline/processors/`         |
| P0-D3  | 宏观择时模块 — 维度①②（趋势动量 + 市场宽度），输出 0-100 仓位映射 | `strategies/macro_timing.py`        |
| P0-D4  | 标的清洗模块 — 剔除流动性 < 500 万、溢价异常、上市 < 60 天          | `strategies/universe_filter.py`     |
| P0-D5  | 波动率倒数加权组合优化                                               | `strategies/portfolio_optimizer.py` |
| P0-D6  | ATR 动态移动止损 + 宏观得分骤降强制减仓                              | `strategies/risk_manager.py`        |
| P0-D7  | 每日盘后主流程编排脚本 (Data → Factor → Signal)                    | `orchestration/daily_pipeline.py`   |
| P0-D8  | 消息推送模块 (至少支持一种通道：飞书/PushPlus/邮件)                  | `orchestration/notifier.py`         |
| P0-D9  | 自研轻量回测循环 v0.1：支持 T+0/T+1 区分、动态仓位上限               | `backtest/custom_loop.py`           |
| P0-D10 | Streamlit 单页面信号面板：今日信号 + 触发原因 + 持仓 + 净值          | `dashboard/`                        |

**验收标准 (Gate Criteria — 全部通过才算 P0 完成)**:

- [ ] **闭环验收**: 在任一交易日盘后运行 `daily_pipeline.py`，能成功从 Akshare 拉取数据、计算宏观打分、生成交易信号、推送到手机
- [ ] **回测正确性**: 用自研回测循环对「沪深 300 ETF 单标的买入持有」策略回测，生成的净值曲线与沪深 300 指数实际走势的年度收益率偏差 < 1%
- [ ] **T+0/T+1 正确性**: 分别对一只 T+1 ETF（如 510300）和一只 T+0 ETF（如 513100）回测，验证交收日期差一天
- [ ] **数据护栏有效**: 手动注入一条"单日涨跌幅 25%"的脏数据，确认 pipeline 阻断并报警
- [ ] **信号可追溯**: 任意一条信号推送中，用户能清晰读到"因为什么触发、建议做什么、仓位多少"
- [ ] **无未来函数**: `tests/` 中至少有一个测试用例验证 T 日计算不依赖 T+1 及以后的数据

### Phase 1 — 因子增强与回测验证 (Factor Enhancement & Rigorous Backtest)

> **一句话目标**: 截面多因子打分体系建立，并通过严苛的样本外回测验证策略的统计有效性。

| 维度               | 内容            |
| :----------------- | :-------------- |
| **前置条件** | P0 全部验收通过 |

**交付物清单**:

| #      | 交付物                                                                                                               | 对应模块                                                  |
| :----- | :------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| P1-D1  | 因子注册表`factor_registry.yaml` 初始化，≥ 8 个因子（动量、波动、成交量、估值等），每个因子附带数学公式与代码路径 | `config/factor_registry.yaml`                           |
| P1-D2  | 因子计算模块完整实现 +`make factor-check` CI 脚本                                                                  | `factor_engineering/`, `scripts/validate_registry.py` |
| P1-D3  | 因子预处理管道：去极值 (MAD)、标准化 (Z-Score)、行业/市值中性化                                                      | `factor_engineering/preprocessor.py`                    |
| P1-D4  | 截面多因子加权打分模块 + 换手率惩罚                                                                                  | `strategies/cross_sectional.py`                         |
| P1-D5  | Alphalens 因子评估报告：IC 均值/IR/分位数收益图（至少对每个因子输出一份）                                            | `factor_engineering/evaluator.py`                       |
| P1-D6  | 宏观择时维度③④⑤逐步接入（③波动率 → ④资金流向 → ⑤信用利差，按数据质量逐个验证后上线）                         | `strategies/macro_timing.py`                            |
| P1-D7  | 组合优化升级为风险平价 (Risk Parity) + Ledoit-Wolf 协方差收缩                                                        | `strategies/portfolio_optimizer.py`                     |
| P1-D8  | 完整回测报告：2015-2021 样本内训练 + 2022-2024 纯样本外测试                                                          | `backtest/`                                             |
| P1-D9  | vectorbt 适配器封装，用于快速对比验证自研引擎结果                                                                    | `backtest/vectorbt_adapter.py`                          |
| P1-D10 | 绩效归因报告：Brinson 分解（择时贡献 / 选股贡献 / 交互效应）                                                         | `backtest/analytics.py`                                 |

**验收标准 (Gate Criteria)**:

- [ ] **样本外回测达标**: 2022-2024 样本外年化收益率 ≥ 8%，夏普比率 ≥ 0.8，最大回撤 < 20%（样本外表现允许比样本内打 5 折）
- [ ] **参数稳定性**: 核心参数在 ±20% 邻域内变动时，样本外夏普变化 < 30%（即不存在"参数孤峰"）
- [ ] **因子质量**: 每个因子都有 IC 均值（绝对值）> 0.02 或 IR > 0.3，且分位数收益图呈现明显单调性
- [ ] **震荡市识别**: 人工标注 2-3 段已知震荡区间（如 2019 年 5-11 月），在这些区间内系统信号频率相比趋势市下降 > 50%
- [ ] **回测引擎一致性**: 同一策略在自研引擎与 vectorbt 上的日收益率序列相关系数 > 0.9999
- [ ] **因子注册表 CI 通过**: `make factor-check` 无报错，所有因子双向一致

### Phase 2 — ML/DL 模型引入 (Machine Learning Integration)

> **一句话目标**: 用 LightGBM/XGBoost 替代或辅助线性因子打分，并建立防过拟合的实验追踪体系。

| 维度               | 内容                  |

**交付物清单**:

| #     | 交付物                                                                  |
| :---- | :---------------------------------------------------------------------- |
| P2-D1 | LightGBM 分类器（预测未来 N 日胜率）与回归器（预测未来 N 日收益率）封装 |
| P2-D2 | Purged K-Fold 交叉验证实现（含 Embargo 隔离带）                         |
| P2-D3 | 基于 DuckDB 的轻量实验追踪表（超参数、训练/验证集划分、IC 衰减曲线）    |

**验收标准 (Gate Criteria)**:

- [ ] **因子动量监控**: 建立各因子滚动 3 个月 IC 监控机制，连续 3 个月 IC 为负的因子自动降权

## 8. 附录：关键量化认知约束 (从 background.md 提炼的硬约束)

*以下约束在 Agent 生成代码时作为 Prompt 中的 System Instruction 注入。*

1. **收益率**: 因子计算与模型训练使用对数收益率 `ln(P_t / P_{t-1})`；展示与盈亏计算使用算术收益率
2. **复权**: 技术指标计算**必须使用前复权**数据
3. **撮合**: T 日信号 → T+1 日开盘价/均价成交；A 股 ETF T+1 交收，跨境/商品 ETF T+0 交收
4. **成本**: 所有回测强制扣除双边佣金 ≥ 0.15% + 滑点
5. **因子形式**: 写连续数学公式（Z-Score），不写布尔规则（`if RSI > 80`）；绝对价格不能做因子
6. **数据时滞**: 宏观数据严格按 `publish_date` 对齐，不使用时序上尚不可知的信息
7. **非平稳性**: 所有因子必须通过 ADF 平稳性检验或进行一阶差分后再使用
