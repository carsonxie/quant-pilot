# Quant-Pilot 使用说明（首次使用手册）

> 本手册面向**第一次接触本项目**的使用者，按"从零到日常使用"的顺序编排。
> 相关背景与规范见 `docs/spec.md`（业务定义）、`docs/background.md`（项目背景）、`README.md`（命令速查）。
>
> **一句话定位**：这是一个 ETF 量化**辅助决策**系统 —— 它每天盘后告诉你"应该持有什么、偏离多少、建议怎么调"，
> 但**不会自动下单**，买卖由你在券商 App 手动执行（系统会把执行结果记下来，用于后续核算与对照）。

---

## 0. 前置条件（一次性）

你需要准备：

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（本文示例为 PowerShell）；Mac/Linux 同理 |
| Python | 由 `uv` 自动管理，**无需手动安装 Python** |
| 网络 | 能访问新浪财经 / akshare 数据源（境外访问可能需代理） |
| 资金账户 | **不需要**。系统默认以"研究模式"运行；真实资金由你决定何时、是否接入 |

## 1. 快速开始（30 分钟内跑通）

在项目根目录（含 `pyproject.toml` 的目录）执行：

```powershell
# 1) 安装依赖（首次，约 1-3 分钟）
uv sync

# 2) 拉取数据（首次为全量，约 1-2 分钟；之后不要再用这个命令，用 daily 增量）
uv run fetch-data

# 3) 运行每日盘后流程（生成信号，写入数据库）
uv run daily

# 4) 打开面板查看
uv run streamlit run dashboard/app.py
#    浏览器访问 http://localhost:8501
```

到这里你已经能看到：**宏观状态、今日信号、策略目标持仓**。

> ⚠️ 常见提示：`fetch-data` 结束时可能打印质检信息（历史份额折算跳变）。
> 当前 12 条已知跳变**已登记**（`equity_events` 表），会显示为"已登记权益事件（info）"而不再阻断；
> 若出现**未登记**的 critical，处理方式见第 6 节。

## 2. 需要你填写什么（配置文件）

**唯一配置文件**：`config/settings.yaml`。只列你可能需要改的部分，其余保持默认。

### 2.1 项目元数据

```yaml
project:
  mode: "research"          # research(默认) | paper | real —— 建议长期保持 research/paper
  strategy_version: "v0.2"  # 策略版本标识；修改策略公式时才需提升
```

### 2.2 ETF 池（最常改的地方）

见第 3 节。

### 2.3 交易成本（费率与滑点）

```yaml
trading_cost:
  scenario: "legacy_stress"     # 成本情景名（当前为旧压力情景，非校准值）
  commission_rate: 0.00075      # 单边佣金率（研究假设）
  min_commission_per_trade: 0.0 # 每笔最低佣金
  slippage_base: 0.0015         # 滑点下限（占价格）
  impact_coefficient: 0.005     # 冲击项（金额/日均额 × 系数）
```

> 涉及资金/成本参数的修改，**请先确认**你的实际费率（券商 App 里能查到），再改这里并记录原因。

### 2.4 再平衡与调仓规划

```yaml
rebalancing:
  account: null            # ← 录入账户后，把账户 ID 填在这里；null = 只出研究目标
  band_points: 0.05        # 偏离触发带：5 个百分点（示例值）
  min_trade_amount: 500.0  # 常规调仓最小金额（元）；只约束常规调整
  valid_days: 3            # 建议有效期（天）
  cooldown_days: 5         # 止损退出后冷却期（天）
```

### 2.5 基准研究配置（可选）

```yaml
baselines:
  label: "research_example..."
  initial_cash: 100000.0
  weights: { "510300": 0.15, ..., "__CASH__": 0.20 }   # 合计必须 = 1
```

> `baselines` 是**研究示例**（来自讨论稿的 股70%/黄金10%/现金20%），**不是你的投资建议**。
> 想用自己的配置，把 `weights` 换成你的目标比例（总和必须为 1、含 `__CASH__`），并把 `label` 改成你自己的名字。

## 3. 如何添加/修改 ETF 池

### 3.1 添加一只 ETF

在 `config/settings.yaml` 的 `universe:` 段按格式追加一行（按类别放入对应分组）：

```yaml
universe:
  broad_base:                       # 分组名只影响归类，不影响逻辑
    - {symbol: "510300", name: "沪深300ETF", market_type: "A股", settlement: "T+1", index_name: "沪深300"}
    # ↓ 你新增的（示例）
    - {symbol: "588080", name: "科创板50ETF", market_type: "A股", settlement: "T+1", index_name: "科创50"}
  cross_border_commodity:
    - {symbol: "513180", name: "恒生科技ETF", market_type: "跨境", settlement: "T+0", index_name: "恒生科技"}
```

五个字段的含义：

| 字段 | 说明 | 常用取值 |
| --- | --- | --- |
| `symbol` | 6 位代码 | 沪深 ETF 以 5/1 开头 |
| `name` | 显示名称 | 任意 |
| `market_type` | 市场类型 | `A股` / `跨境` / `商品` |
| `settlement` | 交收规则 | A股 ETF = `T+1`；跨境/商品 = `T+0` |
| `index_name` | 跟踪指数（研究元数据） | 用于同指数对照 |

添加后执行：

```powershell
uv run fetch-data     # 重建数据（首次拉取新代码的历史）
uv run daily          # 让新标的进入池子评估
```

系统会自动：派生交易所（按代码）、写入产品契约表、按产品应用涨跌板（默认 10%）、
**跨境类自动要求 NAV 检查**（缺 NAV → 禁止新买，但允许继续持有）。

### 3.2 关于"自由添加"的边界

- ✅ 可以自由增删 A股/跨境/商品类 ETF；
- ⚠️ 新标的必须有可获取的历史数据（先单独试跑一次确认数据源有该代码）；
- ⚠️ 加入池子 ≠ 一定会被买入：系统还要过流动性（日均成交额 ≥ 500 万）、上市天数（≥ 60 交易日）、
  溢价/NAV 检查、宏观仓位上限等"四层池"筛选。

## 4. 每日运行与你能看到什么

### 4.1 每日一条命令

```powershell
uv run daily
```

适合在**交易日收盘后**执行（例如 15:30 之后）。它依次完成：

```
增量拉数 → 数据质检(阻断/放行) → 宏观择时(仓位上限) → 四层池(哪些可交易)
→ 选品与权重(波动率倒数, ≤5只, 单只≤30%) → 风控(ATR止损/骤降)
→ 今日信号落库 → 目标组合落库 → [可选] 调仓建议 → 手机推送(可选)
```

### 4.2 终端摘要（示例）

```
[模式] research | 策略版本 v0.2 | 数据截止 2026-09-18 | 宏观scope a_share
[宏观择时] MacroScore(composite=15, cap=0%, regime=ranging, ...)
[标的清洗] 14 只通过: ...
[组合优化] 目标权重: ...
[交易信号] 共 N 条:
  510300 BUY 0.0% → 12.3% | 宏观45分(...); 波动率倒数(1/σ)加权12.3%...
  ...
[调仓建议] 账户 REAL-1 | 新增 3 条 ...   ← 只有配置了账户才出现
  BUY 510300 1,200 份 ≈ 12,000 元 (费 9) | 首次建仓 12.3% ...
```

### 4.3 面板看到什么

`uv run streamlit run dashboard/app.py`：

| 区块 | 内容 |
| --- | --- |
| 运行状态 | 最近一次运行的时间/数据截止/推送结果；失败会红色提示 |
| 宏观卡 | 宏观得分、趋势状态、**仓位上限**、ETF 代理宽度 |
| 今日信号 | 每只标的：方向（BUY/SELL/HOLD）、目标仓位、触发原因 |
| 策略目标持仓 | 目标仓位 > 0 的标的（**模拟目标，不是实际持仓**） |
| 实际 vs 目标 | 如果你录入了账户：每个标的的目标/实际/偏离/是否越界 |
| 待处理建议 | 未执行的建议清单（份额/参考价/优先级/依赖/有效期/反馈状态） |
| 净值对照 | B0（买入持有）/ B1（阈值再平衡）与你账户的独立净值曲线（首日=100） |
| 行情与宏观趋势 | 目标持仓标的归一化价格、宏观得分历史 |

### 4.4 手机推送（可选）

设置环境变量后 daily 会自动推送信号摘要：

```powershell
$env:PUSHPLUS_TOKEN="你的token"   # PowerShell；token 只放在环境变量，不写入任何文件
uv run daily
```

### 4.5 单标的诊断（Phase 1.1，2026-09-29 起）

同一面板入口的第二个模块（左侧/顶部切换"单标的诊断"），用于**下单前自查**：
输入或选择一只 ETF／股票，查看它的指标、评分与规则状态。它**不产生买卖建议**，
不改变策略池和账户；风险状态仅为"正常／警戒／防御"。

| 视角 | 内容 |
| --- | --- |
| 我的持仓 | 由选定账户的实际 ETF 份额确定（真实/模拟区分）；未配置账户时提示，不显示伪持仓 |
| 观察名单 | 手动维护的独立名单（加入不进入策略可交易池；移除不删除持仓/行情/诊断历史） |
| 探索 | 输入 6 位代码或名称 → 确认身份→ 查看详情；结果不会自动加入观察名单 |

详情页包含：评分卡（技术风险分 0-100、状态、完整度、触发）、问题清单、
**近六个月日 K 线**（MA20/60/200 与布林带可开关，成交量/成交额切换；均线使用更长历史计算，
不因图只显示六个月而截短）、指标原值与分项贡献、模板生成的解释（无 LLM）。

使用要点：
- 打开详情会先读上次结果；数据未更新到"最近已完成交易日"时自动受控更新一次（会话内冷却，
  重复切换标签/重绘不会重复抓取）；也可点「手动刷新」强制重取。接口失败会保留上次结果并提示。
- 评分规则为显式"研究示例"（`diag-v0.1-research`，见 `config/diagnostics.yaml`）：
  数值未经验证，仅表示规则下的关注程度，**不是涨跌概率**。
- 数据口径：ETF 用不复权价，股票用后复权价（均已在页面标注）；若行情窗口内有未核验的
  权益事件（拆分/折算），相关跨事件指标会**暂停并说明原因**，总分为空——缺失不视为低风险。
- 休市日无新增数据属正常；短历史标的（次新股/新上市 ETF）长窗口指标会显示为空，不补造。
- **条件检查**（页面下半部分，与技术分单列、不混算）：
  - 股票：营收/归母净利/扣非同比、TTM、经营现金流质量、资产负债率、短期偿债覆盖、净资产、PE-TTM/PB 及自身历史分位（`cond-v0.1-research` 研究示例阈值；亏损/负净资产不给"便宜"结论）；
  - ETF：跟踪标的/规模/费率/近 20 日日均成交额/快照买卖价差/折溢价（当日净值缺失或与价格不匹配时显示"无法评估"，不解除既有跨境禁买规则）；
  - 状态为 **未触发 / 关注 / 重点复核 / 无法评估 / 不适用**；"跟踪质量、底层估值映射"两项本轮**暂缓**（缺可比全收益指数等数据），表中以"不适用 + 原因"显式展示，不补造数据。

## 5. 如何录入交易记录 / 执行反馈

系统把"应该做什么"和"实际做了什么"分开管理：

```
策略目标(Target) → 交易建议(Proposal) → 执行反馈(Feedback) → 真实账户(Account)
```

### 5.1 录入真实账户初始状态与日常交易（推荐唯一入口）

1. 参考模板 `docs/account_events_template.csv` 准备 CSV：

```csv
event_time,event_type,symbol,side,shares,price,amount,fee,reference,note
2026-09-01 10:30:00,initial,,,,100000.0,,,start,"初始现金10万"
2026-09-02 10:05:00,trade,510300,BUY,2000,4.50,,4.50,tx001,"买入2000份"
2026-09-03 14:00:00,deposit,,,,20000.0,,,dep002,"追加资金"
```

2. 导入（重复导入自动去重，可放心重跑）：

```powershell
uv run account-import --account REAL-1 --name "项目账户" --mode real --csv events.csv
```

3. 把账户接进调仓建议：在 `config/settings.yaml` 写 `rebalancing.account: "REAL-1"`，下次 daily 就会生成
   "目标 vs 你的实际"的买卖建议。

**事件类型速查**：

| 事件 | 用途 |
| --- | --- |
| `initial` | 账户起点（现金；持仓写在 `payload_json` 里） |
| `deposit` / `withdrawal` | 入金 / 出金 |
| `trade` | 买卖成交（`side=BUY/SELL`，含费用） |
| `fee` | 单独费用 |
| `dividend_accrual` / `dividend_payment` | 分红应收 / 到账 |
| `share_change` | 份额变动（拆分/折算） |
| `correction` | 更正错误记录（保留原记录） |

### 5.2 执行反馈（可选，用于追踪"有没有照做"）

收到建议后，你可以（在面板"待处理建议"里对照建议 ID）：

- 成交了 → 录入成交反馈（或直接用 5.1 的 `trade` 事件，**二选一，不要重复**）；
- 没执行 → 记录"未执行/延迟/拒绝"及原因。

系统会保留部分成交、超额、未执行的事实，不会替你"补账"，也不会把没做的事当成做了。

> ⚠️ **单写进程约束**：`daily`、`account-import`、基准模拟、迁移演练**不要同时运行**（DuckDB 单写）。
> ⚠️ **一条成交只走一个通道**：直接记事件 **或** 反馈联动，不能两边都记。

## 6. 已知数据问题与正确处理

| 问题 | 现象 | 正确处理 |
| --- | --- | --- |
| **历史份额折算跳变（I-09）** | 某天价格突然 −50%/−80% 等 | 已登记 12 条到 `equity_events` 表；`fetch-data`/`daily` 质检会自动放行（info）。若出现**未登记**的跳变阻断：`uv run python scripts/register_equity_events.py --check` 查看，人工核验后 `--apply` 登记。**不要用全量 fetch-data 绕过**。 |
| **跨境 ETF 缺 NAV（I-03）** | 跨境 ETF 不出买点/显示"禁新买" | 属保守设计：缺净值数据时禁止新增买入（持仓保留）。解锁需接入 NAV 数据源（Phase 1）。 |
| **质检阻断（负价格/超涨跌板）** | daily 中途退出，状态 blocked | 查看日志中 critical 明细；确认是否为权益事件（→ 登记）或真实脏数据（→ 人工处置），处理后重跑 daily。 |
| **真实极端行情** | 20% 板产品单日 ±20% | 系统按产品跌涨板放行，不会改写数据。 |

**一个数据异常不确定怎么处理时**：先跑 `--check` 看是否已知巨幅跳变；再对照基金公告/行情软件确认；
仍不确定时记录到 `docs/PROJECT_MEMORY.md` 的"未解决问题"，不要静默跳过或手工改库。

## 7. 如何用输出指导买卖（核心工作流）

### 7.1 每日 10 分钟流程

1. **看宏观卡**：仓位上限是 0% 就该空仓等待 —— 没信号是正常输出，不是故障。
2. **看今日信号**：`BUY/SELL` 是策略意图；`HOLD` 表示无变化。
3. **看调仓建议（已配置账户时）**：
   - 每条建议含：方向、份额、参考价、估算费用、**优先级**、**有效期**、**依赖条件**；
   - **优先级顺序**：风险退出(止损) > 常规卖出 > 常规买入 > 依赖卖出资金的买入；
   - **依赖条件**（如 `SELL:510300`）= 先卖出成功、资金到位后再买；卖出没做成，买入要相应缩减/延后。
4. **手动执行**：在券商 App 按建议下单（系统不会替你下单）。
5. **录入成交**：用 `account-import`（5.1）或反馈（5.2）记录真实结果。

### 7.2 建议里的关键字段怎么解读

| 字段 | 含义 | 注意 |
| --- | --- | --- |
| 参考价 | T 日收盘价 | **参考**，实际成交价以你下单为准 |
| 份额 | 已按 100 份整手、可卖份额、现金与费用估算 | 现金不足时系统会缩减并把原因写进备注 |
| 有效期 | 过期建议会标记 `expired`，不再累计 | 过期后按最新建议重算 |
| 偏离 band | 常规调仓触发带（示例 5 个百分点） | 未越界不调仓；风险退出不受 band 限制 |
| 冷却 | 止损退出后 N 天内不给该标的买单 | 防止在下跌趋势里反复进出 |

### 7.3 三种策略各自的意义

| 账户 | 行为 | 用途 |
| --- | --- | --- |
| **A（你的账户）** | 系统建议 → 你人工执行 | 检验"择时+选品+风控"是否值得 |
| **B0** | 按固定配置买入后不再调整 | 判断"不再平衡"的路径 |
| **B1** | 固定配置 + 阈值再平衡 | 判断"再平衡本身"的效果 |

对照看净值：A 长期跑不过 B1，说明主动策略没创造增量 —— 这本身就是有价值的结论。

## 8. 绩效与对照怎么看

### 8.1 基准模拟（研究示例配置）

```powershell
uv run baseline --strategy B0 --start 2019-01-02 --end 2026-09-11   # 买入持有
uv run baseline --strategy B1 --start 2019-01-02 --end 2026-09-11   # 阈值再平衡
uv run baseline --strategy B0 --write-account                        # 同时写成模拟账户（面板可见）
```

结果写入 `data/backtests/`（NAV 序列 + 摘要），并登记到 `experiments` 表（含失败留痕）。

> 示例配置为**研究用途**（非你的真实 SAA），且价格口径为不复权（不含分红/权益事件）。

### 8.2 绩效报告的口径（务必理解）

- **金额核对**：期末权益 − 调整起点 − 净外部入金 = 投资盈亏；持仓/分红/费用分项单列，
  "未解释差额"应为 0（不为 0 会显式披露）。
- **入金不算收益**：资产增加但收益率不变（有专项测试验证）。
- **日线近似**：现金流时点按"日终估值点"近似，TWR 为近似值 —— 报告会标注，不要当成精确值。

## 10. 安全边界（重要）

1. **系统不会自动下单**，任何买卖都由你人工执行。
2. `mode: research/paper` 下所有输出均为研究/模拟；改 `real` 也**不会**自动启用真实资金策略。
3. **Phase 0.5 完成 ≠ 允许实盘**：真实账户启用需另行评估（账户核对、配置确认、前瞻运行证据、你明确决定）。
4. 本项目是辅助工具，**不构成投资建议**；回测与模拟结果不代表未来收益。
5. 真实持仓前请确认已完成 I-09 方案2（权益事件入账）；在那之前，持有会拆分/折算的标的时账本可能失真。

## 11. 遇到问题怎么办

| 症状 | 排查 |
| --- | --- |
| `uv: command not found` | 安装 uv（见 README 顶部）；或确认已在项目根目录执行 |
| `fetch-data` 大量失败 | 数据源限流/网络；稍后重试。已入库的历史不受影响 |
| daily 报 `DataQualityError` | 按第 6 节处理（先 `--check`，再决定登记或人工处置） |
| 面板打不开 | 确认 Streamlit 进程在运行；端口默认 8501 |
| 建议与直觉不符 | 先看"触发原因"字段（宏观/权重/风控/偏离/冷却 会写明）；仍疑惑时把该条贴给我 |
| 想改参数 | 改 `config/settings.yaml`；涉及资金/成本/风险参数的修改请说明原因并记录 |
| 中文日志乱码（Windows） | 属终端 GBK 显示问题；命令仍是正常执行的，可用 `uv run ... 2>&1 | Out-File log.txt -Encoding utf8` 查看 |

**停止运行**：`Ctrl+C` 即可（daily 与面板都不会常驻后台）。

## 12. 术语小表

| 术语 | 含义 |
| --- | --- |
| 目标权重 / 实际权重 | 策略希望你持有的比例 / 你账户当前实际比例 |
| band（带宽） | 偏离超过该阈值才触发常规调仓（示例 5 个百分点） |
| 四层池 | 配置范围 → 产品候选 → 当日可交易 → 实际持仓 |
| NAV | 净资产 = 现金 + 持仓市值 + 应收 |
| 冷却 / 重新进入 | 止损退出后一段时间不给该标的买单，之后需重新满足条件 |
| B0 / B1 / A | 买入持有基准 / 阈值再平衡基准 / 主动策略 |
| 权益事件 | 分红、拆分、份额折算等会改变份额或价格基准的事件 |
