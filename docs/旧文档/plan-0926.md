## 2. 实施原则

- 复用已验证模块和当前依赖，不先重构全项目，不按概念数量机械拆出大量服务。
- SAA只作基准；B0、B1、主动策略及真实项目资金分别记账，不强制核心／卫星分仓。
- 默认用隔离测试数据、研究配置和模拟账户验证；不触发真实下单或真实资金策略启用。
- 工程正确性优先：A类纠偏在受影响路径继续验收前修正；不先按旧公式写完再返工。
- 只补齐Phase 0原定剩余功能，再进入Phase 0.5；若已有充分证据则直接衔接，避免重复开发。
- 每批完成“实现＋针对性验证＋进度记录”，满足退出条件后继续下一批，不每个小任务都等待确认。
- 仅在业务定义确实冲突、必要真实信息无法推断、权限不足或不可逆操作时询问用户；普通技术选择自行决定并记录。
- 研究样例可先跑通，不要求用户现在提供真实SAA比例；样例必须标记用途，不能自动升级为真实配置。

### M0：先核对，不凭勾选判断完成

检查仓库状态和未提交改动、入口命令、依赖锁文件、数据库schema、当前策略／推送／面板、关键测试与最近运行记录。保留用户未提交工作，不做破坏性重置。

重点核实T0.8、T0.9、T0.10；记录实际剩余项及其与旧task的差异。测试优先运行已有的相关确定性用例；首次基线不直接运行可能写真实账本或发送通知的日任务。

审计表覆盖spec §9的C01–C23，每项包含：实际证据、是否受影响、优先级、关联模块／批次、验证方式、历史结果影响、状态。区分“已核查不受影响”“已修正并验证”“未实现留待对应阶段”“受阻”。

创建docs/task-phase0.5.md，包含Phase 0补项和M2–M7的原子任务；保留旧task。新任务记录需求／纠偏ID、依赖、产出、验收、状态和证据位置。提交现状摘要后继续实施，不停在只写计划。

### M1：Phase 0收尾及正确性修正

按spec §8.1补齐实际缺失的回测、推送或面板。保留旧策略版本，修正1/σ和1/σ²命名与行为、费用、成交时序、ATR优先级、数据时效及宏观scope等受影响路径。

在旧账户实现不足时，先使用明确标记的模拟账户／最小状态适配器验证闭环，不把旧目标当作真实持仓。基础模拟账本先按M2契约组织，后续扩展导入与持久化，不实现两套互不相容的计算。

回测需要独立手工期望值，覆盖现金、份额、费用、权益事件和下一可交易时段。推送集成用测试通道或模拟发送验证，保留通知结果；真实外发另按用户已有授权执行。

退出条件是spec §8.1有证据且相关A类问题关闭；缺少网络或权益数据时记录阻塞，继续不依赖该来源的工作，不能虚报整阶段通过。

### M2：账户、状态与安全迁移

先确定四类对象和事件接口，再建持久化。逻辑实体建议如下，现有表能兼容时扩展，名称不必照搬：

| 实体 | 核心关联／边界 |
| --- | --- |
| account、account_event、position_lot | account_id＋mode，事件来源去重，可卖份额与批次关联 |
| account_snapshot | 从可信起点和事件生成，包含估值时点；缓存不能替代事件事实 |
| target、target_weight | 完整权重（含现金／明确退出）、策略版本、数据／池／配置版本 |
| proposal、execution_feedback | 建议引用target与账户状态；一条建议可关联多笔反馈 |
| instrument、universe_version | 产品规则／属性生效时间、历史池成员与检查结果 |
| run、experiment | 代码、数据、参数、模式、时点、结果位置与失败状态 |
| schema_migration | 迁移版本、执行状态与核对摘要 |

真实成交和模拟成交可使用同一账本更新函数，但由不同输入渠道产生，并以mode／account隔离。通知、策略计算或用户“已查看”都不能产生真实成交。

实现初始状态、入金／出金、成交、费用、分红应收与到账、份额变化、更正事件；支持手动录入或标准CSV。来源不明的历史信号不能迁移成真实成交；不能还原成本时从可信起点开始。

统一写入口和事务，重复导入不增加第二笔事件；并发导入／日任务采用明确协调方式。具体迁移保护见§5。

### M3：数据与ETF池

扩展产品、规则、available_at和版本契约；将现有筛选改为pass／fail／unknown／not_applicable，分别给出新买许可、可卖状态与原因。

把配置范围、同指数产品比较、当日筛选和实际持仓分开。已有数据不足以覆盖全A宽度时准确命名代理，不为满足名称临时全量爬取所有股票。

保存池成员生效区间和来源；历史缺口标记条件性研究。缺NAV时禁止依赖该检查的新买，停牌时保留持仓；复权修订使受影响缓存失效，不能只重画净值。

实现轻量产品对照表与相关性诊断，报告窗口、有效样本和未知字段；缺历史规模／跟踪数据时留空说明，不伪造产品优劣。

### M4：把目标转换成真实可行的建议

保留策略目标生成器；将“与账户比较、计算数量、现金约束、有效期及状态”抽为共用规划逻辑。策略函数接收截至决策时点的数据，不从任意最新数据库读未来内容。

顺序遵守spec §5.5：有效性约束 → 账户约束／暂停 → 风险退出与暴露限制 → 常规调整 → 费用及持有期过滤。风控修改目标后，规划器不能重新放宽目标。

首版再平衡按绝对百分点偏离触发，越界资产调回目标；允许整数份额与费用造成剩余偏离。目标未变、未执行、部分执行、明确清零分别处理。

卖出依赖买入、建议替代／过期、反馈迟到、重复日任务和冷却／重新进入都有状态记录。现金预留只影响可用量，不减少净资产；作废或完成后释放，避免重复建议多次占用。

### M5：基准与主动策略共用执行基础

实现B0固定初始配置买入持有、B1固定目标加阈值再平衡；A接入现有主动目标生成器。共用规划、权益事件、成本与账本规则，三个账户独立。

B0／B1固定相同初始映射与权重。标准研究先使用无外部现金流；出入金测试采用预先声明的同额同日现金流，B0新增现金的政策显式。

B1检查日依交易日历计算；止损等主动策略规则不自动加到B0／B1。产品无法交易时记录偏离与原因，不通过伪成交让基准满足权重。

使用固定研究配置完成同口径示例和版本记录，不在Phase 0.5搜索最优SAA比例或把最好回测直接启用。

### M6：基础绩效、记录与面板

完善已开始记录的run／experiment信息，包括失败试验。基础报告给出净资产、净外部入金、盈亏、持仓／分红／现金贡献及实际费用，差额单列。

收益采用spec的现金流口径；只有日线时明确现金流时点约定。参考价滑点可分析但不重复从现金扣费。不做完整因子Alpha、Brinson或风险平价报告。

扩展现有单页：真实／模拟标签、账户更新时间、实际／目标、现金、待处理建议、反馈入口、数据问题、净值与B0／B1／A对照。将计算结果交给展示层，避免在UI重新实现收益与权重公式。

### M7：验收、切换与交接

在隔离副本上完成迁移、重跑和恢复演练；对照§6的关键场景和spec P05-D1–D8记录证据。复用已有充分证据，不为凑测试数量重复验证。

真实事件不被重算覆盖；旧策略和结果保留版本，新报表标明口径和可信起点。正常运行只启用一个明确建议来源，研究基准不参与真实指令合并。

更新README的实际运行／导入方式、必要的项目记忆和新任务状态；报告已完成、未实现的未来模块、阻塞及恢复方法。Phase 0.5完成不等于允许实盘，也不自动进入Phase 1开发。

## 5. 数据与版本迁移方案

1. 先检查Git状态并保留现有改动；在隔离开发分支／工作区实施，不提交密钥或数据仓库。
2. 识别数据性质：真实事件、模拟事件、目标信号、可重建行情／缓存、旧报告。无法识别的记录不得自动归为真实。
3. 在受控停止写入或采用数据库支持的一致方式后建立备份和manifest，记录schema、关键表行数、账户份额／现金；不能随意复制正被写入的数据库当作可靠备份。
4. 在副本上演练版本化迁移；优先新增表／列、适配旧读接口，避免直接删除旧事实。验证迁移失败不会留下半笔账户事件。
5. 旧信号保留为信号；有可信来源的真实事件才迁移入账。新账本从可信起点建立，无法重建的历史明确标注。
6. 修改权重、复权、费用或时序时产生新策略／数据版本；列明需失效的缓存和需重跑的结果，不改写旧报告的含义。
7. 用同一固定输入核对迁移前后应保持的事实。可重建结果允许因纠偏不同，差异需对应修正ID。
8. 切换前保留恢复路径。若切换后已有新真实事件，不能简单恢复旧备份丢弃它们；应保留并核对新事件后恢复或前向修复。

重建缓存与重算模拟结果可自动执行；不可恢复的删除、真实账本重置、资金用途改变不得作为默认迁移动作。

## 7. 任务维护与后续阶段

docs/task-phase0.5.md由Codex依据实际实现生成，不从本文逐句机械复制。每个任务应能独立审阅和验证，维护关联需求／纠偏、依赖、产出与证据。完成一次可验收改动后同步状态；不要仅凭文件存在勾选完成。

每次工作结束在审计记录或项目记忆中写明：当前批次、已通过验证、未关闭项、下一步及必要命令。续跑时先读该记录和Git状态，不重做已完成工作。

Phase 1在Phase 0.5验收后另拆任务，先做少量因子和模块对照；Phase 1.5再做风险／因子归因与策略治理；ML及其他策略保持后续候选。当前任务完成后输出交接摘要，不自动扩展范围。
