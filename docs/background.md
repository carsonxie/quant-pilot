- **知识背景**：统计学 + 计算机科学双本硕。具备极强的代码工程能力（熟练使用 Python、深度学习框架）和数学推导能力（熟悉时间序列分析）。
  - *导师点评*：这是量化领域最硬核的"护城河"。你不需要从零学编程或高等数学，你的主要挑战在于 **"打破用做互联网大数据的思维，来做极低信噪比的金融数据"** 的惯性。

## 第二部分：Quant-Pilot 项目愿景与架构边界 (Project Vision & Spec)

**1. 项目核心定位 (The "Why")**

这不是一个会自动帮你赚钱的印钞机，而是一个 **"剥离人类情绪、严格基于统计概率、每日自动推演交易逻辑"** 的辅助决策机器人。系统的终点是"生成高质量的交易建议"，人工审核并手动执行，绝不包含全自动实盘下单接口。

**2. 核心技术栈选型 (The Stack — 经导师审核优化)**

*放弃重型工业级框架（如 Qlib），采用轻量、灵活、高扩展性的现代 Python 数据科学栈，以匹配 ETF 标的池规模和个人开发者的精力限制。*

- **数据处理**：`Polars` (主打高性能时序与截面计算) + `pandas` (兼容复杂生态) + `numpy`。
- **回测引擎**：`vectorbt` (向量化回测，快速原型验证) + **自研轻量回测循环** (处理 T+0/T+1 混合撮合、动态仓位上限等复杂场景)。
- **数据源**：`Akshare` (主数据源，免费无限制) + `JQData` (聚宽，用于交叉验证复权数据质量及获取深度财务数据)。
- **因子评估**：`alphalens-reloaded`。
- **存储架构**：`DuckDB` 为主数据仓库（单一真理之源）+ `Parquet` 按需物化因子缓存（精简双层架构，消除多库一致性问题）。
- **前端展示**：`Streamlit`（P0 单页面信号面板）+ `Plotly`。

**3. 系统的五层决策漏斗 (The 5-Layer Logic)**

1. **宏观择时 (决定总仓位)**：采用**五维度复合打分系统**（趋势动量30%、市场宽度25%、波动率20%、资金流向15%、宏观环境10%），输出 0-100 的市场状态得分，映射到仓位上限，防范系统性股灾。*(P0阶段先实现趋势与市场宽度)*
2. **标的清洗 (决定可交易池)**：分析池包含 50-100 只 ETF，但严格剔除流动性枯竭（日均成交额<500万）、严重溢价、上市不足 60 天的标的。
3. **因子打分 (决定买谁)**：融合动量、波动率、成交量等截面因子，对剩余 ETF 排序，**最终实际持仓只集中在全市场最优的 3-5 只 ETF 上**。
4. **组合优化 (决定买多少)**：P0 阶段采用波动率倒数加权；P1 升级为风险平价（Risk Parity）或 Ledoit-Wolf 协方差收缩，确保高波动标的（如科创50）不会主导组合回撤。
5. **风控执行 (决定何时卖)**：叠加基于 ATR（真实波动幅度）的动态移动止损，以及宏观择时得分骤降时的全局强制减仓。

*系统每天盘后推送到手机。你只需要按以下 6 步走，10 分钟内完成。*

## 第三部分：已点亮的金融量化认知树 (Mastered Concepts)

*（这部分是你已经掌握的"防雷基石"，在让 Agent 写代码时必须作为硬约束注入 System Prompt）*

1. **防范"未来函数"**：永远不能用 T 日收盘价在 T 日买入，必须假设在 T+1 日开盘/均价买入。宏观数据必须做时间戳对齐（Forward-fill），并使用 `publish_date` 字段（实际可获取日期）而非统计日期来过滤可用数据，严禁未来泄露。
2. **正确使用收益率**：模型训练和因子计算必须使用**对数收益率 ln(P_t/P_{t-1})**（时间线性可加），展示和计算实际盈亏时使用算术收益率。
3. **回测的"反作弊"支柱**：必须使用**前复权**数据计算技术指标；强制扣除**滑点和双边佣金**（ETF 至少双边 0.15%）；严格遵守标的的 **T+1（A股ETF）或 T+0（跨境/商品ETF）** 撮合限制。
4. **主观逻辑的"连续因子化"**：不写 `If RSI > 80` 的布尔规则，写连续的数学公式（如 Z-Score）。警惕非平稳性（绝对价格不能做因子，所有因子必须通过 ADF 检验或一阶差分后使用）。
5. **因子评估裁判系统**：利用 **IC/IR** 衡量因子预测力与稳定性，利用**分位数收益图**观察单调性。

## 第五部分：导师视角的"死亡清单"与避坑指南 (The Graveyard of Retail Quants) 🚨

*这是整个文档最重要的一部分。90% 的个人量化项目不是死于代码写不出来，而是死于以下这些隐蔽的"致命陷阱"。每个陷阱现在都配有**可测试的假设**和**量化验收标准**，你需要把它们集成到回测或 CI 检查中。*

---

### 致命坑 1：震荡市的"均线打脸"与摩擦损耗 (The Whipsaw Grinder)

- **现象**：你的宏观择时第一层用了均线交叉。在单边牛市/熊市中表现完美，但在长达一两年的**宽幅震荡市**中，均线会频繁金叉死叉。系统不断发出"买入-跌破止损-卖出-再金叉买入"的信号。
- **死因**：每次交易扣除 0.15% 的双边摩擦成本，加上滑点，一次"假突破"可能磨损 1%-2% 的本金。震荡市一年下来，策略没亏，但本金被手续费和滑点"凌迟"了 20%。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H1.1**: 引入市场宽度和波动率作为宏观打分的组成维度后，在人工标注的震荡区间（如 2019 年 5-11 月、2023 年 2-9 月）内，系统发出的调仓信号频率应相比纯均线系统下降 **> 50%**。
  >
  > **H1.2**: 引入换手率惩罚（新旧信号仓位差异 < 15% 不调仓 + 最低持仓 3 天）后，年化换手率应下降 **> 30%**，且样本外年化收益率下降幅度 **< 2%**（即惩罚机制只砍噪音交易，不砍有效信号）。
  >
  > **H1.3**: 在回测中单独拆出"摩擦成本贡献"一栏：震荡年份（如 2018、2023）的摩擦成本占总收益的比例不应超过 **25%**。
  >
- **量化验收标准** 🆕：
  - [ ] 人工标注 3 段已知震荡区间，在这些区间内的信号频率相比趋势市下降 > 50%
  - [ ] 换手率惩罚开启前后对比：换手率下降 > 30% 且年化收益下降 < 2%
  - [ ] 震荡年份的摩擦成本 / 总收益 < 25%

---

### 致命坑 2：流动性幻觉与"收盘价陷阱" (The Liquidity Mirage)

- **现象**：回测时，系统发现某个冷门行业 ETF（如"某细分化工 ETF"）动量极强，回测按"收盘价"成交，资金曲线飙升。实盘时你买入 2 万元，发现盘口挂单只有几千块，你一买就把价格打高了 1%，一卖就砸跌停。
- **死因**：回测引擎假设你拥有无限流动性，且能以收盘价成交。实盘中，你的资金体量虽然只有 10 万，但对于日均成交额只有 200 万的 ETF 来说，你的市价单足以造成巨大的**冲击成本 (Market Impact)**。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H2.1**: 在第二层标的清洗中硬性剔除日均成交额 < 500 万的 ETF 后，回测的样本外夏普比率下降幅度应 **< 0.1**（即被剔除的冷门 ETF 的策略收益本身就无法在实盘中兑现，剔除它们不会真正伤害策略表现）。
  >
  > **H2.2**: 对通过清洗但仍属于"中小流动性"（日均成交额 500 万-2000 万）的标的，施加「交易金额 / 日均成交额 × 0.5%」的冲击成本惩罚后，回测中该标的的扣费后 Alpha 应大幅缩水——这证明冷门标的的超额收益本质是流动性幻觉。
  >
  > **H2.3**: 对于计划持仓金额 / 标的日均成交额 > 0.5% 的情况，系统应自动触发警告。
  >
- **量化验收标准** 🆕：
  - [ ] 剔除日均成交额 < 500 万标的前后，样本外夏普下降 < 0.1
  - [ ] 回测引擎中实现冲击成本模型：滑点 = max(0.15%, 交易金额 / 日均成交额 × 0.5%)
  - [ ] 标的清洗模块包含流动性集中度检查：单标的计划持仓 / 日均成交额 > 0.5% → 警告

### 致命坑 3：参数挖矿与回测幻觉 (Parameter Mining / Overfitting)

- **现象**：你让 Coding Agent 帮你跑网格搜索，寻找最优的动量周期和均线参数。Agent 告诉你："当动量周期=17天，均线=23天，止损=1.8倍ATR时，历史年化高达 35%，夏普 2.5！"你兴奋地拿去买实盘，结果一个月后亏损 15%。
- **死因**：金融数据信噪比极低。你找到的不是"市场规律"，而是 **"对历史噪音的完美拟合"**。参数越多、搜索空间越大，过拟合的概率呈指数级上升。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H3.1 (参数平原测试)**: 如果最优参数为 P\*，则在 P\* ± 20% 邻域内的所有参数组合，其样本外夏普比率的变化幅度应 **< 30%**。如果只有 P\* 有效而相邻参数崩溃，说明 P\* 是过拟合的"孤峰"，必须弃用。
  >
  > **H3.2 (样本外衰减)**: 2015-2021 样本内最优参数应用到 2022-2024 样本外时，夏普比率衰减应 **< 50%**（样本外夏普 ≥ 样本内夏普 × 0.5）。若衰减 > 50%，说明样本内存在严重过拟合。
  >
  > **H3.3 (奥卡姆剃刀)**: 核心策略参数总数应 **≤ 5 个**（不含因子权重）。参数数量增加时，必须提供样本外增量 R² 的统计显著性检验（p < 0.05）。
  >
- **量化验收标准** 🆕：
  - [ ] 最优参数 ±20% 邻域内，样本外夏普变化 < 30%
  - [ ] 样本外夏普 ≥ 样本内夏普 × 0.5
  - [ ] 策略核心参数 ≤ 5 个
  - [ ] 每次新增参数时附带样本外增量 R² 显著性检验

### 致命坑 4：数据源的"静默失效" (Silent Data Decay)

- **现象**：系统稳定运行了半年，突然有一天你发现生成的信号全乱了。排查了三天代码没发现问题，最后发现是 Akshare 底层爬取的某个网站改版了，或者 Akshare 某次更新悄悄改变了"前复权"的计算算法，导致历史价格数据在某一天出现了巨大的断层。
- **死因**：开源免费数据源缺乏 SLA（服务等级协议）保证。数据污染会直接导致因子计算崩溃，进而产生错误的交易信号。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H4.1**: 在每日数据拉取后，自动计算相邻两天收益率。若出现单日涨跌幅 > 15%（ETF 极少出现）或成交量为 0 但价格变化的异常记录，**阻断流程并报警**。手动注入测试数据验证阻断逻辑。
  >
  > **H4.2**: 每周用 JQData 拉取核心宽基 ETF 数据，与 Akshare 同日数据计算 Pearson 相关系数。若 < 0.999，触发警报。回溯测试：选取过去某段 Akshare 已知出现过数据问题的时期，验证该系统能否捕获。
  >
  > **H4.3**: 数据 Pipeline 中记录每次拉取的元数据（行数、时间范围、缺失值比例）。若当日拉取行数与过去 20 日均值偏离 > 3 个标准差，触发"数据异常"警报（而非直接阻断，因为也可能是真实的市场事件如新 ETF 上市）。
  >
- **量化验收标准** 🆕：
  - [ ] 手动注入单日涨跌幅 20% 的脏数据 → Pipeline 阻断并报警（自动化测试）
  - [ ] 双源交叉验证脚本每周自动运行，相关系数 < 0.999 → 报警
  - [ ] 数据元数据监控：行数偏离 > 3σ → 报警

### 致命坑 5：人机对抗与心态崩溃 (The Execution Gap)

- **现象**：系统发出了明确的"清仓止损"信号（因为触发了 ATR 移动止损，且宏观择时得分跌破 20）。但你看着盘面，觉得"已经连跌了 5 天，技术指标严重超卖，明天肯定要反弹"，于是你**主观覆盖了系统信号，选择扛单**。结果第二天发生了黑天鹅事件，直接跌停，你的年度收益瞬间清零。
- **死因**：量化交易最大的敌人不是代码，而是**人类在面临亏损时本能的多巴胺和皮质醇反应**。一次不守纪律的"主观干预"，就能毁掉系统半年的积累。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H5.1 (信号归因清晰度 → 执行率)**: 当系统推送信号时附带清晰的多层级归因（如"宏观得分从 45 降至 18（趋势转空+宽度恶化），触发全局仓位从 70% 降至 30%"），人工执行信号的遵从率应**显著高于**仅推送"卖出 40% 仓位"的简洁版信号。
  >
  > **H5.2 (最大亏损预期 → 扛单概率)**: 在实盘前，回测报告专门列出"最大单笔亏损"和"最长连续亏损次数"。实盘中，当实际亏损落在回测历史分布的 1 倍标准差范围内时，人工选择扛单的概率应**趋近于 0**（因为你已经打过预防针）。
  >
  > **H5.3 (盘中看盘 → 干扰率)**: 盘中看盘的次数与"主观干预系统信号"的次数呈正相关。目标：盘后看一次 → 盘中看盘次数 = 0。
  >
- **量化验收标准** 🆕：
  - [ ] 回测报告中包含"最大单笔亏损"和"最长连续亏损次数"章节
  - [ ] 交易日志中记录每次"人工否决信号"的原因，每月复盘否决的正确率
  - [ ] 盘后 30 分钟完成 Checklist（第四部分）后，全天不再打开交易软件

### 致命坑 6：市场风格切换与因子失效 (Regime Shift)

- **现象**：你的动量因子在 2019-2020 年的核心资产牛市中大杀四方。但到了 2021 年之后，市场风格切换为"微盘股反转"和"高股息红利"，动量因子开始持续回撤，买入即被套，卖出即反弹。
- **死因**：没有任何一个单一因子能永远有效。金融市场存在"因子拥挤"和"风格轮动"。当全市场都在用动量时，动量就会失效。
- **可测试的假设 (Testable Hypotheses)** 🆕：
  > **H6.1 (因子低相关性)**: 因子池中任意两个因子在 2019-2024 全周期的 Spearman 秩相关系数绝对值应 **< 0.6**。若某对因子相关性 > 0.6，它们本质在衡量同一个东西，需要合并或剔除其中一个。
  >
  > **H6.2 (因子动量择时)**: 当某个因子滚动 3 个月 IC 均值 < 0 时，将其在截面打分中的权重自动减半。回测对比：有因子动量择时 vs 无因子动量择时，样本外最大回撤应降低 **> 20%**。
  >
  > **H6.3 (风格适应验证)**: 将历史分为不同风格区间（如 2019-2020 动量牛市、2021 小盘反转、2022-2023 价值红利），策略在每个区间的年化收益均应为正——证明多因子体系具备风格适应能力，而非依赖单一市场环境。
  >
- **量化验收标准** 🆕：
  - [ ] 因子池中任意两个因子的 Spearman 秩相关系数绝对值 < 0.6
  - [ ] 有因子动量择时 vs 无因子动量择时：样本外最大回撤降低 > 20%
  - [ ] 策略在每个风格区间（动量/反转/价值）的年化收益均为正
